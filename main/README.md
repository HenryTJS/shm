# main：内部疲劳机主样本

自采的疲劳试验数据，用于回答「寿命进度能不能在线估出来」。方法只有一条，写在 `cdio_baseline/`。

## 1. 数据

| 项 | 内容 |
| --- | --- |
| 试件 | **27 组**（`001`–`027`），5 Hz 正弦压-压疲劳，服役期渐进损伤 |
| 通道 | AE 25 列逐 hit 特征（能量、峰值、计数、波形因子…）+ 应变 + 5 路 FBG |
| 时间轴 | 全组统一 **10 Hz**；块 = 500 点 = 50 s = 250 循环 |
| 载荷 | 016–019 为 10 / 1.0 kN，020 为 8 / 0.8 kN；022 / 027 是「循环 + 静力」有上限的另一类试验 |
| 入库口径 | **看板 24 组**（003–014 / 016–027）；001 / 002 / 015 不进建库、不进统计、不出包 |

## 2. 方法

**累积能量寿命百分比预测**（`cdio_baseline/live_predictor.py`）：

- 时钟：AE 累积对数谱能量（CElog），逐窗累计；
- 相似度：组成指纹 KNN，在库内历史试件中找最近邻；
- 容量反解：把当前累计量放到库容量的贝叶斯分布里，反解寿命百分比（附 90% 区间）；
- 因果性：只用截至当前窗口的信息 + 库内历史试件，**不用当前试件终值、不用标签**。

输入是窗级流（0.1594 s 一窗，至少含 `ae_SpectralEnergy`），输出逐窗寿命百分比、区间、两估计器分歧度与可信度告警。

## 3. 结果

| 指标 | 24 组留一 |
| --- | --- |
| 寿命百分比 MAE | 均值 **9.6** / 中位 **8.8** 个百分点 |
| 末期点估计均值 | **78.9**（真值 100） |

末期偏低是结构性的：库容量跨试件差 6.1 倍，而早期曲线又几乎重合，末期可用信息最少。读法应是**看区间上界**，不单读点。

**两个估计器拆开看**（016 留一，逐点对比）：融合不是免费的，轨迹匹配是负资产。

| 估计器 | MAE | 偏差 |
| --- | --- | --- |
| `bayes_pct`（纯容量反解） | **6.77** | −6.64 |
| `life_pct`（动态门控融合） | 13.93 | −13.86 |
| `life_pct_fixed`（固定 0.7 融合） | 15.94 | −15.85 |
| `knn_pct`（轨迹形状匹配） | **19.92** | −19.80 |

原因与下面一条同源：库轨迹归一化后几乎重合，没有形状可匹配，匹配结果被噪声主导。
若要保留这套方法，应把 `sources` 简化为**纯贝叶斯容量反解**。

## 4. 边界

- **这个量是"记录进度"，不是损伤度**，也**不是成果**：它是「零损伤信息」的下界基线。
  AE 累积能量与寿命近似线性（`u@90% = 0.90`，即寿命最后 10% 只贡献 10% 能量），
  因此它能排时间、不能分辨损伤程度 —— 不声称在线预警、不给剩余寿命。
- 判定它是"时钟而非损伤计"用的是三个与「累计和天然平滑」无关的量：`u@90%`（累积能量达总量 90% 时的
  寿命分数）主样本 **0.90**、C1 恒幅 **0.89**、C3+C4 变幅/谱载 **0.22–0.99**（后者时钟失效，
  才因此携带信息）；逐循环能量 CV C1 **0.40** vs C3+C4 **1.36**；容量离散度 max/min **6.1 倍**。
  6.1 倍比曲线偏离直线的那点信息（最大 6.1%、中位 0.5%）大两个数量级 ⇒ 承载不了损伤信息。
- **不支持定位**（本项目没有外部断裂时刻真值，几何也不足以做定位）。
- 输入口径必须与建模一致（0.1594 s 窗、同频带同增益），否则累积容量不可比。
- 记录必须终止于破坏，"进度 100%" 才能读成"寿命 100%"。

## 5. 怎么跑

```bat
cd main
python run.py --list                    rem 任务矩阵
python run.py --task cdio               rem 在线进度预测（示例流 example_stream.csv）
python run.py --task dashboard          rem 看板数据包：留一预测 + 24 组回放包
python run.py --task dashboard --dry-run
```

`--task` 可给多个（`--task cdio dashboard`），`--` 之后的参数透传给底层脚本。
子进程的工作目录 = 脚本所在目录（`main/cdio_baseline/`）。

## 6. 目录

| 路径 | 内容 |
| --- | --- |
| `001`–`027` | 原始数据（外接盘 junction） |
| `cdio_baseline/` | **唯一在用的方法**：`live_predictor.py`（预测）、`export_dashboard.py`（逐组留一）、`build_dashboard_all.py`（看板出包）、`refit_bundle.py` / `compare_bundles.py`（工件与 A/B） |
| `config.py` / `damage_index.py` / `data_loader.py` / `streaming.py` | 旧 D(t) 链路的配置与算法（流式入口、损伤指数、数据加载），现只被 `attic/` 引用 |
| `results/` | 口径收缩过程中的诊断记录（不是交付结论） |
| `attic/` | 已归档的评估链路，不在任何入口被调用 |
